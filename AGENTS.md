### Runtime / Security Notes (2026-09-09)
- **APP_ENV startup guard** (config.py `Settings.validate()`): meanings are explicit — `dev` = development only; `prod` and `production` both normalize to **production** (only these two count as production); **any other value (e.g. `staging`) → startup error**. Production requires (1) `DATABASE_URL` matching `POSTGRES_RE = r"^postgresql(?:[+][\w-]+)?://"` (accepts `postgresql://` and driver-suffixed `postgresql+psycopg://`), (2) `ALLOWED_HOSTS` explicitly set (the dev fallback `localhost,127.0.0.1` does NOT count), and (3) `SECRET_KEY` explicitly set, ≠ the dev fallback `dev-secret-key-change-me-32bytes-minimum`, and ≥32 chars. Any **non-default** `DATABASE_URL` (vs `sqlite:///./student_management.db`) with `APP_ENV` unset → startup error. Dev with a custom DB must set `APP_ENV=dev`. Tests: `tests/unit/test_config_guard.py` (13 cases).
- **TrustedHostMiddleware** is added to the app **only when `APP_ENV=prod`**, using `settings.allowed_hosts`. `Base.metadata.create_all` runs **only when `APP_ENV != prod`** (prod uses Alembic).
- **Access token default = 480 minutes** (`ACCESS_TOKEN_EXPIRE_MINUTES`). `.env.example` updated; dev `.env` files must be updated (they still carry 1440) if token lifetime matters.
- **Login throttle** (`api/auth.py`): in-memory counters keyed by `email|client-IP` behind a `threading.Lock`; 5 failed attempts within 15 min → `429`; counter resets on success; unknown-user failures run a dummy bcrypt check for uniform timing. Single-process only — for multi-instance deployments move the counters to Redis and only trust `X-Forwarded-For` when behind a reverse proxy.
